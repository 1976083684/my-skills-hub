# 面试鸭题库爬虫

从面试鸭网站爬取指定题库的全部题目，生成按难度（简单→中等→困难）排序的 Markdown 清单。

## 触发场景

- 用户提供 `mianshiya.com/bank/<id>` 链接
- "爬取这个题库" / "下载面试题清单" / "保存面试鸭题目"
- "把 XX 面试题爬下来"

## 工作流程

### 1. 获取题库链接

从用户消息中提取面试鸭题库 URL，格式为：
```
https://www.mianshiya.com/bank/<bank_id>?current=1&pageSize=20
```

只需保留 `https://www.mianshiya.com/bank/<bank_id>` 部分即可。

### 2. 确定输出目录

询问或根据上下文确定 Markdown 文件的输出目录。如果用户已经指定了路径，直接使用。

### 3. 执行爬虫脚本

运行 bundled 脚本：

```bash
pip install requests -q 2>&1 | tail -1
python <skill-path>/scripts/scrape.py "<bank_url>" "<output_dir>"
```

脚本会自动：
- 调用 `POST https://api.mianshiya.com/api/question_bank/list_question` 拉取全部题目
- 按难度排序（简单 → 中等 → 困难）
- 生成含序号、题目、难度、链接四列的 Markdown 表格
- 同时输出一份 JSON 数据文件，供后续分类使用

### 4. 知识体系分类

脚本运行完成后，读取生成的 JSON 数据文件，对所有题目进行知识体系分类：

1. 读取 `JSON 数据` 文件，获取全部题目标题
2. 根据题目标题语义，将其归类到不同的知识领域（如：索引、事务与锁、SQL优化、架构与存储引擎等）
3. 每道题只能归属一个分类，避免重复
4. 在 Markdown 文件末尾追加 `## 📋 知识体系分类` 区块，格式如下：

```markdown
## 📋 知识体系分类

### 分类名称1
- 题目1
- 题目2

### 分类名称2
- 题目3
...
```

5. 分类原则：
   - 分类名应简洁，控制在 2-5 个字内
   - 分类数控制在 5-10 个，避免过细
   - 相关性高的题目归入同一分类
   - 面试应用题（如"你在项目中如何..."）归入「实战场景」类

### 5. 展示结果

向用户报告：
- 获取到的题目总数
- 各难度分布（简单/中等/困难）
- 输出文件路径

## 技术原理

面试鸭使用 Next.js 服务端渲染，但题目数据通过内部 API 加载：

- **API 端点**: `POST https://api.mianshiya.com/api/question_bank/list_question`
- **请求体**: `{"current":"1", "pageSize":"200", "questionBankId":"<id>", "tagList":[]}`
- **难度字段**: `difficulty` — `1`=简单, `3`=中等, `5`=困难
- **分页**: 设置 `pageSize=200` 可一次拉取全部（目前最大题库约 50-60 题）

> **注意：** 该 API 只返回题目列表（标题+难度+编号），不含完整答案解析。答案解析需要登录后才能查看。
