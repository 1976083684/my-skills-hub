# 输出模板

整体文件骨架：

```markdown
# 【PRD】<主题> <期次>对齐

| 项目 | 内容 |
| --- | --- |
| 对齐范围 | 模块A（PRD 9）、模块B（PRD 10）…… |
| 依据资料 | 《PRD文件名》（版本，日期）、《原型文件名》（版本） |
| 标记说明 | ✅ 合理可开发 / ⚠️ 遗漏或不完整需补充 / ❌ 矛盾或硬伤需产品确认 |
| 整理日期 | YYYY-MM-DD |

---

# 1. <模块名>

## 第一段：功能预览

- 模块作用：一句话（谁、在什么场景、用它处理什么、结果去哪）
- 页面结构：层级关系（列表 → 详情/页签/弹框）
- 功能预览：
  - 查询：查询字段
  - 新增：表单字段（必填/带出/唯一约束/保存后的下一步）
  - 修改：可改范围、状态限制
  - 删除：勾选规则、级联、引用约束
  - 查看：入口与展示内容（注明仅原型有时写"仅原型有"）
  - 导入：模板 → 校验链 → 失败处理
  - 导出：导出范围
  - 明细维护：页签/字段/联动规则
  - 下游消费：数据流向哪个模块、以什么键关联

## 第二段：逐功能评审

- 查询
  - ⚠️ ……【PRD x.x】
- 新增
  - ✅ ……
- 导入
  - ❌ ……【PRD x.x】
- DB 建表
  - 结论：需新增 N 张表（主/从），PRD 是否有表设计
  - ✅/⚠️ 字段出处情况、缺口
- 与下游关联
  - ✅/❌ 取数键、口径、现状（有代码仓库时写）
```

# 2、3… 其余模块同结构

最后一章：

```markdown
# N. 跨模块关键问题汇总（开发前必须先闭环）

1. ❌ ……（一句话说清影响 + 涉及章节）
2. ⚠️ ……
```

## 写作要点

- 功能预览每项一行嵌套列表，控制在"能看懂页面怎么用"的粒度，不抄字段字典全表。
- 评审按功能分组，组内每条一个标记符号；同一功能可多条。
- "DB 建表"和"与下游关联"为每模块固定小节；其余功能小节按实际有无可增减。
