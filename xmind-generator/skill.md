# XMind 思维导图生成器

从指定目录下的 Markdown 笔记生成 XMind 思维导图。

## 触发场景

- "生成思维导图" / "梳理成xmind" / "一个脑图贯穿所有知识点"
- "生成知识体系" / "全局总结" / "专题总结" / "知识点脑图" → **知识体系模式**

---

## 两种生成模式

本技能支持两种生成模式，通过用户触发词自动切换：

| 模式 | 触发词 | 目标 | 层级 | 细节程度 |
|------|--------|------|------|----------|
| **普通模式**（默认） | "生成思维导图"、"梳理xmind" 等 | 忠实提取笔记内容 | 灵活，按需展开 | 保留关键细节 |
| **知识体系模式** | "知识体系"、"全局总结"、"专题总结"、"知识点脑图"、"总结整个专题"、"精简" | 提纲挈领，一图贯穿全局 | 严格3层（根→章→知识块→要点） | 只保留概念名，去除解释 |

**关键判断逻辑**：用户消息中只要包含「知识体系 / 全局总结 / 专题总结 / 知识点脑图 / 总结整个专题 / 精简 / 分支不要太深」中的任一关键词，**强制切换为知识体系模式**。

---

## 通用工作流程（两种模式共用）

### 1. 通读所有笔记

逐个读取目录下 `.md` 文件，提取核心知识框架。重点关注标题、对比关系、流程步骤、面试题。

### 2. 按模式设计知识树

- **普通模式** → 见下方「普通模式规则」
- **知识体系模式** → 见下方「知识体系模式规则」

### 3. 生成脚本并执行

直接编辑技能目录下的 `generate_xmind.py`，只修改 `build_tree()` 函数构建知识树，然后执行：

```bash
python .claude/skills/xmind-generator/generate_xmind.py "<目标目录>" "<文件名>.xmind"
```

- 参数1：输出目录（必填）
- 参数2：输出文件名（可选，默认"思维导图.xmind"）

### 4. 验证

- 普通模式：文件大小灵活
- 知识体系模式：文件大小应在 10-30KB（过大说明细节太多）
- ZIP 内含 content.xml + meta.xml + META-INF/manifest.xml
- print 语句用英文，避免 Windows GBK 编码错误

## 普通模式规则

逐文件忠实提取内容，适合单篇或少量笔记的详细梳理：

- **层级灵活**：按笔记的自然结构展开，可超过3层
- **保留细节**：关键公式、数值、步骤流程可保留
- **符号允许**：允许使用 ❌✅⚠️ 等标记符号
- **粒度**：每篇笔记独立成章，知识点块数量不限
- **跨文件不合并**：不同文件的重复概念各自展开

## 知识体系模式规则（全局知识体系专用）

当用户触发「全局知识体系」时，必须严格遵守以下设计原则。这些规则优先级高于一切，任何偏离都是错误的。

### 结构约束（硬性）

- **严格3层结构**：根节点 → 第1层(章) → 第2层(知识块) → 第3层(要点)。不允许出现第4层。违反此规则等于生成失败。
- **每章4-7个知识块**：每个二级节点下4-7个子节点，超过则合并，不足则拆分。
- **每块2-5个要点**：每个三级叶子节点下2-5条要点，每条一行，不嵌套。

### 内容约束（硬性）

- **去冗余**：跨文件的重复概念只在一处展开，以最先出现或最核心的文件为准。
- **去细节**：去掉计算公式、逐步流程、具体数值、代码示例，只保留概念名和一句话定义。
- **去符号**：不使用 emoji（✅❌⚠️💡），不用装饰性标记。
- **去解释**：每条要点一句话说清"是什么"，不说"为什么"和"怎么做"。不要展开论证和背景。
- **覆盖优先**：宁可少写两个要点，也要保证所有主要知识点都被覆盖到。

### 内容组织原则

- **渐进有序**：章节按学习路径排列（基础→进阶→实战→原理），每章内知识块也按认知顺序排列（先概念后原理）。
- **对比优先**：对立概念（并发vs并行、公平vs非公平、Future vs CompletableFuture）应放在同一知识块下形成对比。
- **统一术语**：全文使用相同的概念命名，不同文件中同一概念的不同叫法统一为一个。

### 叶子节点写法

每条叶子节点（第三层要点）格式：
- 以概念名/关键词开头，冒号后跟一句话定义
- 示例：`CAS：三个操作数V(内存值) E(预期值) N(新值)，CPU指令级原子`
- 反例：~~`CAS全称Compare And Swap，它通过比较内存值和预期值来决定是否更新...`~~（太啰嗦）

## 代码框架要点

模板脚本 `generate_xmind.py` 提供完整框架：

| 组件 | 说明 |
|------|------|
| `Topic` 类 | `add(title)` 添加子节点，`add_leaf(title)` 添加叶子，`to_xml()` 递归生成 |
| `escape()` | XML 特殊字符转义（`& < > "`） |
| `create_xmind()` | 生成 content.xml + meta.xml + manifest.xml，打包 ZIP |
| `build_tree()` | **唯一需要修改的函数**，构建知识树 |

---

## XMind 文件格式

ZIP 压缩包，包含：

| 文件 | 作用 |
|------|------|
| `content.xml` | 核心数据，`<sheet><topic>` 递归嵌套 |
| `meta.xml` | 作者、创建时间 |
| `META-INF/manifest.xml` | 文件清单 |

命名空间：`xmlns="urn:xmind:xmap:xmlns:content:2.0"`
