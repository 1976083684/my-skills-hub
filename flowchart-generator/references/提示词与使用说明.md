# 流程图两种方式

默认规则：只生成 Markdown 内的纯 Mermaid，不生成 draw.io、SVG 或交付图片目录；未指定或含糊时同样如此，不询问格式。只有用户明确要求 draw.io 时才额外生成指定图的原生编辑源，Markdown 仍保留 Mermaid且默认不引用编辑源；只有明确指定 SVG 时才采用原生 draw.io＋嵌入模型的 SVG，并在 Markdown 引用。

请读取 flowchart-generator/SKILL.md，根据以下流程生成日常维护用的纯 Mermaid Markdown，保存到【Markdown 绝对路径】。

采用清新蓝、绿、橙、灰配色及旧版兼容语法。目标阅读器和 Mermaid 版本为【已知版本或未知】。支持 ELK 时启用 ELK；不支持或无法确认时采用 Dagre 兼容回退，并说明实际布局，不使用无法识别的现代 YAML 配置。不生成 draw.io、SVG、图片目录或另一份文档。不扩展业务、不引用系统分析模板。检查目标版本兼容性，未验证时说明。

## Mermaid 版本与连线

- Mermaid 8.8.3：使用 `graph TB`、双引号节点、`classDef`；不使用 YAML 前置配置、`layout: elk` 或 `flowchart-elk`。虚线标签采用 `A -.->|"说明"| B`。显式设置 `linkStyle default fill:none,stroke:slategray,stroke-width:1px;`，避免路径填充形成黑块；仍异常时检查目标阅读器主题 CSS，不能承诺仅改源码就解决。
- 支持 ELK 的 Mermaid 10.x 集成可试用 `flowchart-elk TB`，需要真实验证加载能力。Typora 1.9 系列曾有可用记录；不能由版本号推断所有环境都可用。
- 现代环境可使用 `config.layout: elk`，但宿主还须实际提供并加载 ELK。Mermaid 11.x 的版本号本身不足以证明有 ELK。
- 用户指定 Dagre 阶梯折线时使用 `curve: "step"`；前置折线使用 `curve: "stepBefore"`。这两项是 Dagre 连线形状选择，不是额外的交付方式，也不能保证固定节点或完全避让。初始化配置必须在目标环境验证，不能把旧版忽略配置误认为生效。
- 不支持配置的旧环境以基础兼容图为准，不伪装成 ELK，也不通过生成图片替代用户要求的纯 Mermaid。

清新配色代码：

```text
classDef process fill:aliceblue,stroke:cornflowerblue,color:darkslategray,stroke-width:1px;
classDef result fill:honeydew,stroke:mediumseagreen,color:darkslategray,stroke-width:1px;
classDef decision fill:oldlace,stroke:darkorange,color:darkslategray,stroke-width:1px;
classDef support fill:whitesmoke,stroke:lightslategray,color:darkslategray,stroke-width:1px;
linkStyle default fill:none,stroke:slategray,stroke-width:1px;
```

按节点业务含义分配 class，不能只声明样式而不应用。

## 提示词二：明确指定 draw.io＋SVG

请读取 flowchart-generator/SKILL.md，根据以下流程生成正式展示用 Markdown，保存到【Markdown 绝对路径】。

先创建原生 `.drawio` 编辑模型，再使用 draw.io 导出嵌入编辑模型的 SVG。采用清新蓝、绿、橙、灰配色，合理规划节点位置、连接端口、正交连线和必要的绕行点，使主流程清楚、依赖线尽量从外围绕行、文字和连线不重叠。

每张图的 `.drawio` 与 `.svg` 保存到 Markdown 同级 `./images/{md文件名不含扩展名}/`；文件名使用可辨识的图标题，如 `订单转换-正式定论.drawio` 与 `订单转换-正式定论.svg`，重名追加序号。Markdown 嵌入 SVG 并链接对应编辑源。不交付 Mermaid 版本，不把普通 Mermaid SVG 当成可返回 draw.io 编辑的 SVG。保持提供的业务关系，检查渲染效果及 SVG 内模型能否恢复。不额外分析系统或引用其他模板。

## 原生编辑源与正式 SVG 实现

默认纯 Mermaid 不执行以下原生编辑源与导出步骤。明确要求 draw.io 时执行第 1 步，校验模型与 Mermaid 的节点、条件、连线关系一致后保存编辑源，不导出 SVG；第 2 至第 5 步仅用于明确指定 SVG。只处理用户指定的图或范围。

1. 创建原生 mxGraph XML：节点含独立 ID、文字、样式和几何坐标；连线通过 `source`、`target` 引用真实节点，设置正交路由、连接端口，必要时提供 waypoints。不要把整图作为单张图片插入 draw.io。
2. 使用 draw.io 实际导出，关键参数为 `--export --format svg --embed-diagram --border 20 --output <目标.svg> <源.drawio>`。调用时安全处理带空格路径；Windows 后台进程使用隐藏窗口。
3. 解析 SVG 中的嵌入模型（通常为根元素的 `content` 属性）；兼容 draw.io 模型编码形式，将恢复后的对象与源文件比较，确认节点、文字、连线端点一致。仅有 SVG 图形、元数据标记或文件后缀都不能证明可编辑。
4. 视觉检查导出结果；条件允许时在 draw.io 用“打开”重新打开 SVG，确认节点和连线可单独编辑，而非普通图片导入。
5. draw.io 不可用或导出失败时保留源模型，说明缺少的导出步骤，不伪造已完成的嵌入模型 SVG。

明确指定 SVG 时的保存结构（默认方式仅保存 Markdown；明确要求 draw.io 时才另存编辑源）：

```text
指定目录/
├─ 流程图.md
└─ images/
   └─ 流程图/
      ├─ 业务流程.drawio
      └─ 业务流程.svg
```

仅明确指定 SVG 时在 Markdown 中添加以下引用；默认方式不添加图片或编辑源链接：

```markdown
![业务流程](./images/流程图/业务流程.svg)
[编辑源文件](./images/流程图/业务流程.drawio)
```

## 现有 Mermaid 辅助脚本

`scripts/render_diagrams.py` 不生成原生 draw.io 模型。它的 `--mode mermaid` 只复制源码；`--mode svg` 仍调用 Mermaid CLI，仅供临时渲染检查，不作为正式方式交付。该脚本的配置不能改变 Typora 内置渲染器。技能保存在用户指定目录，未安装至全局技能目录。
