# 技术设计文档助手 Skill

## 目标

帮助开发者在合适的时机使用技术设计文档：既不让简单任务过度设计，也不让高风险任务遗漏关键方案。Skill 的核心是**判断、选择、裁剪、生成、评审**，不是每次都输出完整母版。

## 何时启用

当用户提出以下任一需求时使用本 Skill：

- 编写、生成、完善或评审技术设计文档/技术方案；
- 开发前评估实现方案、模块职责、数据库或接口变更；
- 设计 MQ、定时任务、增量同步、数据迁移、批处理、并发或一致性方案；
- 需要确定文档类型、标题、模板深度或专项章节。

如果用户只是提出一个极简单、低风险的代码问题，且没有要求设计文档，不要强行生成完整文档；可以简短说明设计影响。

## 必须遵循的工作流

### 第一步：理解任务和现有项目

1. 提取目标、范围、验收标准、影响模块和限制条件。
2. 如可访问项目文件，优先阅读相关需求、现有代码、数据库结构、接口契约和项目规范。
3. 不得臆造类名、字段、接口、业务规则、性能指标或已有系统行为。
4. 缺失信息若影响核心设计，列出关键待确认项；若可合理继续，则明确标注假设。

### 第二步：判断是否需要文档

- 极简单、低风险、局部修改：可不生成独立文档，输出简短方案或 PR 说明即可。
- 普通功能、CRUD、多个方法协作：选择 L1 或 L2。
- 多模块、数据库结构、接口契约、跨系统交互：至少 L2。
- MQ、定时任务、增量同步、批量处理、事务一致性、并发、数据迁移、核心链路、性能/安全风险或难以回滚：选择 L3 或补充对应专项设计。
- 重要技术选择存在长期影响：建议附 ADR，不用 ADR 代替主设计文档。

风险优先于公司规模。不要因为团队小就省略高风险设计，也不要因为团队大就要求每个小改动写长文档。

### 第三步：选择文档类型和标题

默认主文档使用：`《业务/模块名称 + 需求/变更主题 + 技术设计文档》`。

按目标选择：

- 整体方案和选型：技术方案设计文档；
- 总体方案到实现落地：技术设计文档；
- API 契约：接口设计文档；
- 表结构、索引和迁移：数据库设计文档；
- MQ/同步/迁移/性能等复杂主题：专项技术设计文档；
- 重要长期技术决策：ADR；
- 开发完成后交接测试：提测说明；
- 生产操作和恢复步骤复杂：发布与回滚方案。

只有在需要独立维护、跨团队协作或多处复用时，才把专项章节拆成独立文件。

### 第四步：读取规范并裁剪模板

优先读取 `references/设计规范与选择指南.md`，其中包含章节要求、母版、专项补充清单和质量检查项。

按 L1/L2/L3 裁剪：

- L1：背景目标、方案、关键逻辑、必要的数据/接口说明、测试范围。
- L2：增加总体流程、模块职责、异常处理、适用的事务/幂等、配置变更和测试场景。
- L3：增加方案对比、失败恢复、容量/性能、安全、监控告警、发布回滚和风险清单。

仅保留适用章节。不适用章节直接删除，不留空标题。不要为了填满模板制造无意义内容。

### 第五步：生成设计文档

文档应尽量回答：

1. 为什么做：背景、目标、范围和验收标准；
2. 整体怎么做：总体方案、模块关系和核心流程；
3. 具体怎么落地：模块职责、关键逻辑、数据与接口契约；
4. 出错怎么办：异常、事务、幂等、并发、超时、重试、补偿和恢复；
5. 如何验证和上线：测试场景、发布顺序、监控、回滚和风险。

对于不适用的主题明确写“不涉及”是否必要由团队规范决定；通常删除无关章节更简洁。对尚未确认的内容使用 `待确认：...`，不要猜测。

### 第六步：评审和输出

生成后检查：

- 设计深度是否与风险匹配；
- 流程是否闭环，关键分支是否遗漏；
- 数据库、接口、消息契约是否完整且兼容；
- 幂等、事务、并发、失败恢复是否按场景覆盖；
- 测试预期是否可验证；
- 高风险变更是否包含监控、发布和回滚/恢复；
- 是否有空泛重复内容或无依据的事实。

默认输出：
1. 推荐文档类型、级别及原因；
2. 建议文件名；
3. 可直接保存的完整 Markdown；
4. 关键待确认项（如有）。

如果用户只要求评审，按“等级—位置—问题—风险—修改建议”输出，并给出是否建议通过的结论。

## 专项设计要求

### MQ / 消息驱动
至少检查生产触发条件、消息结构/版本、唯一标识、投递可靠性、重复消费、幂等、顺序、事务边界、ACK、重试耗尽、死信、失败记录、人工重放、补偿、对账、积压监控与告警。

### 定时任务 / 增量同步
至少检查增量依据、时间精度、扫描窗口、分页/游标、断点续跑、并发控制、新增/修改/软删除识别、重复和漏数、乱序/延迟、全量增量切换、补数、对账与运行指标。

### 数据库变更 / 迁移
至少检查数据量、DDL/DML 顺序、锁和索引影响、批次与事务、新旧版本兼容、发布顺序、备份、迁移校验、失败续跑、回滚限制和线上观察指标。

### 第三方接口
至少检查契约、鉴权、敏感信息、连接/读取超时、重试条件、幂等、限流、对方不可用、字段兼容、日志、告警、降级和补偿。

### 性能优化
至少检查优化前基线、瓶颈证据、目标指标、方案取舍、副作用、压测方法、容量估算、回归风险和上线观察计划。

## 资源文件

- `references/设计规范与选择指南.md`：完整规范、通用母版、专项补充清单和检查项。
- `references/提示词模板.md`：可复制到全局规则、文档生成、设计评审和编码前确认的提示词。
- `templates/技术设计文档母版.md`：可直接复制并填写的文档模板。

如果运行环境无法读取这些资源文件，继续按本 Skill 中的规则工作，并明确说明没有读取到资源原文；不得声称已加载。
